# Конспект лекции: «Сети. Топология»

## 1. Что такое сеть

**Компьютерная сеть** — система взаимосвязанных устройств, соединённых каналами связи для обмена информацией.

**Сетевой сегмент** — часть сети, изолированная от других частей по физической или логической границе.

### Основные компоненты сети
- Серверная инфраструктура
- Рабочие станции
- Сетевое оборудование
- Точки доступа

---

## 2. Понятие топологии

**Топология сети** — совокупность соединений элементов сети друг с другом, определяющая геометрическую структуру связей и логические правила взаимодействия узлов при передаче данных.

Топология описывает:
1. Физические связи между устройствами.
2. Потоки трафика по сетям.
3. Пути передачи данных.
4. Методы адресации и маршрутизации.

### Ключевые критерии выбора топологии
| Критерий | Описание |
|----------|----------|
| Стоимость | Бюджет на оборудование и инфраструктуру |
| Надёжность | Возможность восстановления при отказе части системы |
| Масштабируемость | Простота добавления новых узлов |
| Производительность | Скорость передачи данных в сети |
| Безопасность | Устойчивость к атакам через сегментацию и изоляцию |

---

## 3. Базовые топологии

### 3.1. Шина (Bus Topology)
Все устройства подключаются к единому коммуникационному кабелю (основной линии). Данные передаются на всех сегментах, но адресация направляет пакеты нужным узлам.

**Характеристики:**
- Недорого в реализации.
- Простая в подключении.
- Устарела из-за низкой безопасности и ненадёжности.
- Любая атака на шину влияет на всю сеть.
- Широковещательные пакеты передаются всем устройствам, что упрощает перехват трафика.
- Обрыв одной точки останавливает работу всей сети.

### 3.2. Кольцо (Ring Topology)
Устройства соединены в замкнутый круг, где каждый передаёт данные только соседу по кольцу.

**Характеристики:**
- Передача данных по принципу «токена».
- Если устройство выходит из строя — сеть не работает.
- Применяется реже, сейчас заменено коммутаторами.
- Трудно масштабировать без остановки сети.

### 3.3. Ячеистая (Mesh Topology)
Каждое устройство подключается к нескольким другим, образуя многогранную структуру путей передачи данных. Позволяет альтернативные маршруты при отказе одного канала связи.

**Характеристики:**
- Максимальная надёжность и отказоустойчивость.
- Сложна в реализации и администрировании.
- Требует больше оборудования и кабелей.
- Высокая устойчивость к атакам на отдельные узлы.
- Сложность контроля трафика по множеству путей.
- Сложность обнаружения скрытых каналов передачи.

### 3.4. Звезда (Star Topology)
Каждый узел подключается к центральному устройству (коммутатору или концентратору). Стандартная топология для современных офисных сетей.

**Характеристики:**
- Отказ одного устройства не влияет на работу остальных.
- Простая в отладке и администрировании.
- Высокая стоимость.
- Изоляция портов, защита от широковещательных атак.
- Центральный узел становится точкой отказа.
- Возможности фильтрации: ACL (Access Control Lists) на уровне коммутатора.

### 3.5. Гибридная топология
Сочетание разных типов топологий в одной сети, часто используется в крупных корпоративных структурах и кампусах.

**Характеристики:**
- Сегментация по функциям.
- Возможность использования разных протоколов на разных сегментах.
- Высокая сложность настройки и администрирования.

### 3.6. Иерархическая звезда (Tree Topology)
Иерархическая структура, где узлы организованы по уровням и общаются через центральные узлы.

**Характеристики:**
- Масштабируемость.
- Управляемость.
- Надёжность.
- Сложность проектирования и реализации.
- Центральный узел становится точкой отказа.
- Возможности фильтрации.

## 4. Концепция DMZ (Demilitarized Zone)

**DMZ** — промежуточная зона между внутренней и внешней сетью, используемая для размещения публичных сервисов организации. Это архитектурный принцип защиты корпоративных систем от атак извне.

**Назначение:**
1. Размещение веб-, почтовых и других серверов, доступных из интернета.
2. Изоляция этих серверов от внутренней сети с чувствительными данными.
3. Снижение уязвимости при взломе внешних ресурсов.

---

## 5. Уязвимости при выборе неправильной топологии

### Логические угрозы
1. Отсутствие сегментации.
2. Паралич сети при атаке на broadcast-трафик.
3. ARP Spoofing (подмена MAC-адресов для перехвата трафика).

### Физические угрозы
1. Отсутствие изоляции портов в хабах.
2. Прямая физическая связь между устройствами (отсутствие шифрования).
3. Открытые точки доступа без аутентификации.

### Атаки типа Man-in-the-Middle (MITM)
1. Атакующий внедряется в сеть (часто через слабый хаб или уязвимый роутер).
2. Подменяет MAC-адреса на уровне коммутатора (ARP Spoofing).
3. Перехватывает данные, проходящие через его устройство.

**Защита:**
1. Использование VLAN и ACL для изоляции сегментов.
2. Шифрование трафика (TLS/SSL).
3. Мониторинг сетевого трафика на предмет аномалий.
4. Регулярное обновление оборудования.

---

## 6. Рекомендации по проектированию защищённых сетей

- **Использование VLAN для сегментации:**
  - Логическое разделение сети на зоны по функциям.
  - Ограничение широковещательного трафика между сегментами.
  - Простота управления и администрирования.
- **Реализация принципа наименьших привилегий:**
  - Ограниченный доступ только к необходимым ресурсам.
  - Изоляция DMZ от внутренней сети.
  - Контролируемое движение трафика между сегментами.
- **Мониторинг сетевого трафика.**

## 7. Сетевое оборудование

### 7.1. Хабы (Hubs)
Концентратор — активное устройство первого уровня OSI, которое принимает данные на один порт и распространяет их на все остальные. Простой повторитель без какого-либо интеллекта. (Устарел)

**Принцип действия:**
- Работает на физическом уровне.
- Не хранит таблицу MAC-адресов.
- Повторяет сигналы, увеличивая их уровень.

**Проблемы безопасности:**
- Все устройства получают весь трафик.
- Отсутствие сегментации.
- Атака типа MITM (Man-in-the-Middle).

### 7.2. Коммутаторы (Switches)
Коммутатор — активное устройство второго уровня OSI, которое управляет передачей данных между устройствами сети на основе MAC-адресов.

**Принцип действия:**
1. Коммутатор хранит таблицу (ARP/CAM Table), связывающую порты и MAC-адреса.
2. Принимает кадр на один порт, проверяет таблицу.
3. Если адрес найден — передаёт только нужному устройству.
4. Если не найден — широковещает всем портам (кроме входящего).

**Изоляция портов:**
- Позволяет изолировать устройства.
- Можно настроить VLAN для логической сегментации без физического подключения.
- Port Security.

### 7.3. Маршрутизаторы (Routers)
Маршрутизатор — устройство третьего уровня OSI, осуществляющее маршрутизацию данных между разными сетями.

**Принцип работы с IP-адресами:**
1. Маршрутизатор хранит таблицу маршрутизации (Routing Table).
2. Принимает пакеты, проверяет адрес назначения.
3. Пересылает пакет по оптимальному пути к целевой сети.

**Таблица маршрутизации содержит:**
1. Network Address.
2. Маску подсети.
3. Gateway.
4. Интерфейс.
5. Метрика.
6. Доп. сведения (тип маршрута, флаг по умолчанию, состояние канала, административное расстояние).

---

## 8. Краткие выводы

- Топология определяет структуру связей и влияет на безопасность, производительность и стоимость сети.
- «Шина» и «кольцо» устарели из-за низкой отказоустойчивости и безопасности.
- «Звезда» — стандарт для офисов, но центральный узел является точкой отказа.
- «Ячеистая» топология обеспечивает максимальную надёжность, но сложна и дорога.
- DMZ и VLAN — ключевые инструменты сегментации и защиты.
- Хабы небезопасны, коммутаторы и маршрутизаторы позволяют реализовать изоляцию и фильтрацию.

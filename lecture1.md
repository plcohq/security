# Конспект лекции: «Модели угроз и их анализ»

## 1. Что такое модель угроз

**Модель угроз** — это не просто список проблем, а структурированное описание того:
- как может быть нарушена безопасность системы;
- какие последствия это может вызвать;
- какие меры защиты необходимы.

### Три основных компонента
1. **Угрозы** — что может навредить.
2. **Атаки** — как именно это может быть реализовано.
3. **Последствия** — к чему приведёт нарушение безопасности.

---

## 2. Порядок построения модели угроз

1. Определить границы и характеристики системы.
2. Выявить возможные негативные последствия.
3. Определить объекты воздействия.
4. Определить источники угроз и модели нарушителей.
5. Определить способы реализации угроз.
6. Построить сценарии реализации угроз.
7. Определить актуальные угрозы и оформить результат.

---

## 3. Подходы к созданию моделей угроз

- **Стратифицированный анализ** — «слоёный пирог», анализ по уровням системы.
- **Сценарный подход** — «Что если…?».
- **Анализ уязвимостей**.
- **SWOT-анализ** — Strengths, Weaknesses, Opportunities, Threats.

---

## 4. Классификация угроз

### По уровню воздействия
| Уровень | Примеры |
|---|---|
| Критический | DDoS-атаки, кража данных |
| Значительный | ВПО, фишинг |
| Минимальный | Ошибки конфигурации, слабые пароли |

### По субъекту
- Внешние.
- Внутренние.
- Физические.

### По вектору атаки
- **Сетевые** — DDoS, сниффинг.
- **Прикладные** — RCE, SQLi, XSS, CSRF.
- **Пользовательские** — фишинг, социальная инженерия.
- **Физические** — доступ к серверу.

### По времени
- Постоянные.
- Временные.

## 5. Основные модели угроз

| Модель | Автор / описание | Применение |
|---|---|---|
| **PDR** (Protection–Defense–Recovery) | Традиционная модель защиты | Защита критической инфраструктуры |
| **CIA-Triad** | Конфиденциальность, целостность, доступность | Классификация требований безопасности |
| **Stratified Threat Model** | Разделение по уровням системы | Сложные сети и приложения |
| **MITRE ATT&CK** | Глобальная база тактик атак | Анализ методов злоумышленников |
| **NIST SP 800-30** | Federal Risk Assessment Guide | Государственные стандарты США |
| **ISO 27005 / 27019** | Международные стандарты по рискам | Глобальная защита данных |

## 6. Методы оценки рисков

### Базовая формула
\[
R = T \times V \times C
\]

Где:
- **T** (Threat) — вероятность реализации угрозы;
- **V** (Vulnerability) — уровень уязвимости системы;
- **C** (Consequence) — возможный ущерб от инцидента.

Также используется упрощённая формула:
\[
R = P \times C
\]
где **P** — вероятность, **C** — потенциальный ущерб.

---

## 7. Качественная оценка рисков

**Качественная оценка** — определение уровня риска на основе экспертных суждений, опыта и классификационных шкал, без точных числовых расчётов.

### Методы
- **Оценка экспертами** — сбор мнений специалистов по ИБ.
- **Delphi-метод** — анонимный многоэтапный опрос экспертов с обратной связью до достижения консенсуса.
- **Мозговой штурм** — коллективное генерирование идей для выявления рисков.

### Плюсы и минусы
| Плюсы | Минусы |
|---|---|
| Быстро | Субъективность |
| Учитывает опыт и интуицию | Влияние личных мнений |

---

## 8. Матрица рисков

Оценка проводится по осям:
- **вероятность**;
- **воздействие**.

### Цветовые зоны
- 🟢 **Зелёная** — низкий риск, достаточно мониторинга.
- 🟡 **Жёлтая** — средний риск, нужно планирование действий.
- 🔴 **Красная** — высокий риск, требуются немедленные меры.

---

## 9. Количественная оценка рисков

**Количественная оценка** — оценка рисков с использованием численных значений, часто в денежном выражении. Требует исторических данных и статистического анализа.

### Методы
1. **Численная оценка в денежном эквиваленте**
   \[
   R = P \times C
   \]

2. **Анализ деревьев отказов**
   - определить нежелательное событие;
   - выбрать основные пути к нему;
   - добавить промежуточные события (AND, OR, XOR);
   - заполнить листинг базовых событий;
   - рассчитать вероятность каждого сценария.

3. **Метод Монте-Карло**
   - статистическое моделирование;
   - множество случайных вариаций параметров;
   - например, 10 000 симуляций;
   - результат — диапазон возможных потерь.

4. **FMEA** — Failure Mode and Effects Analysis
   - анализ последствий отказов компонента;
   - используется в проектировании оборудования и ПО.

### Этапы FMEA
1. Идентификация системы и компонентов.
2. Определение режимов отказа.
3. Оценка последствий.
4. Ранжирование и приоритизация.

## 10. Практический пример: интернет-магазин одежды

**Объект:** интернет-магазин с онлайн-оплатой.

| Шаг | Действие | Результат |
|---|---|---|
| 1 | Идентификация активов | БД пользователей, платёжный шлюз, сервер приложений |
| 2 | Выявление угроз | Фишинг, DDoS, SQL-инъекции, утечки данных |
| 3 | Оценка уязвимостей | Недостаточное шифрование, открытый порт, слабые пароли |
| 4 | Расчёт рисков | \( R = T \times V \times C \) для каждого сценария |
| 5 | Разработка контрмер | Шифрование, MFA, WAF, обучение персонала |

---

## 11. Пример расчёта риска для платёжной системы

**Угроза:** кража данных при перехвате транзакции.

- **T** = 0,4 × 70% = **0,28**
- **V** = 0,5 — средняя уязвимость, парольная аутентификация
- **C** = **$5 000 000**

\[
R \approx 0,28 \times 0,5 \times 5\,000\,000 \approx \$700\,000
\]

**Рекомендация:** высокий риск — внедрить двухфакторную аутентификацию.

## 12. Пример матрицы рисков для интернет-магазина

| Риск | Вероятность | Воздействие | Приоритет |
|---|---|---|---|
| Фишинг | Высокая | Средний | Средний |
| DDoS на платёжный шлюз | Средняя | Высокий | Высокий |
| Уязвимость в API | Высокая | Высокий | Высокий |
| Слабые пароли админов | Низкая | Средний | Мониторинг |
| Стихийное бедствие (пожар) | Очень низкая | Очень высокий | Страхование |

---

## 13. Основные выводы

- Моделирование угроз — это **проактивный подход** к безопасности.
- Комбинация нескольких моделей даёт лучший результат.
- Оценка рисков требует учёта не только вероятности, но и последствий.
- Практика важнее теории — инструменты нужно применять на реальных кейсах.
